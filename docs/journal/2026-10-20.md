## v7-10 test mode: dead order ids retried forever — FIXED (index.js makeReplaceOrder)
Root cause: TEST mode by design. order-manager pulls each unfillable test order after TEST_CANCEL_MS (60 s; events
`order_canceled reason test-auto-cancel`, "canceled after 68-76s") and deliberately does NOT clear the strategy's pending
state (the position is simulated). The replace guard (index.js, "never replace an order the broker has finished with")
then answered every later reprice `skipped:canceled`, and since daf2194 (10/04) a replace that did not take effect
reverts the book's price. Net: v7-10's simulated give-up / cover ladder / open walk froze ~60 s after each placement,
every day since it went to test on 10/16. Counts (10/16-10/20): open-reprice 841, cover-giveup 713 (10/20: 513, of which
546 order_replace_skipped events on one order #1008363672783), cover-reprice 269, raise-walk 198, cover-stall 23.
So v7-10's paper results since 10/16 understate its covering (give-ups never escalated) — read them with that caveat.
Fix: (1) test order the engine pulled -> the replace is simulated (`order_simulated by test-pulled`), the book moves,
nothing is sent; (2) live order the broker finished -> clearDeadOrderState now runs on the replace path too, so the next
pass places a NEW order (idempotent with the poller), except replace-pair bookkeeping rows (superseded-by-fill / id
unknown) whose state is kept on purpose; (3) REPLACED with a tracked live successor -> reprice the successor and adopt
its id. Test: candle-spread-dead-order-replace (21). Live path already cleared dead orders via the poller; the live-mode
residue was the 10/14 race (10x `400 Order in status REJECTED cannot be replaced` before the poller caught up), bounded.
Not changed (note): in test mode a broker REJECT of an unfillable test order (10/20 14:00 "250:1 liq to short option
value") still clears the simulated cover via the poller's DEAD branch — a test-only distortion, 1 case on 10/20.

## Give-up regime study (scripts/candle-spread/study-giveup-regime.js; data/sweeps/giveup-regime-2026-10-19) — study only
User question: when a give-up fires, can momentum or where price sits in the 15m/60m bands tell "truly give up, cover at
the mark now" from "wait, the pullback is still likely"? Earlier work only changed WHEN a give-up fires (10/06 trigger
re-sweep, 10/10-11 candle triggers, 10/08 trend urgency — all rejected) or the allowance for everyone (10/06, 5/7.5/10%).
Method: roster v6-v9 x 10/20/40, 821 days, baseline settings; read-only hook runDay5m opts.giveUpTap (terminals reproduce
the baselines exactly, so it is inert). Event = a position's FIRST give-up; the cover legs' mark is then followed bar by
bar (favourable extreme / close / adverse extreme). Arms are per-position counterfactuals (governor/book effects NOT
re-simulated): payNow (mark + tick, unbounded), capK (current rule with allowance K: fill now if mark + tick <= break-even
+ K x W, else rest there; cap0 = wait for break-even), hold, actual. 75,911 points-trigger give-ups (+ 21,760 cover-to-open escalations on v6-v8,
reported separately). Rules selected on the early half of 2023-25 days, tested on the late half and on 2026.
- Paying at the mark loses in EVERY bucket of EVERY feature at every width (z-scored 15-min speed, 5/15/45-min adverse
  move, run since last swing, 15m/60m %B, riding the band, 15m/60m/A trend, distance from 9EMA/midline); CIs exclude 0 in nearly every bucket.
  v7-10: payNow -$189k vs the current 5% rule (CI -219k..-150k), uncovered 801 -> 0; v9-10 -$345k; v7-40 -$592k.
- Momentum does NOT predict "kept running": came back to break-even later 60-75% in every speed/band bucket, slightly
  MORE often after big/fast runs and when riding the band (10W z15>=2: 64%; riding 15m band 4+ bars: 73%).
  The user's rule as written (z15>=2 & beyond the 15m band, or fast & 60m trend against -> pay now) lost $ on early AND
  late halves at every width (10W -33k / -58k), for 160-320 fewer uncovered positions; worst day same or worse.
- Only TIME separates: after 15:00 came back 28% (10W) / 33% (20W) / 46% (40W). Paying now after 15:00 still costs $
  (10W -26k/-66k) for ~500 fewer uncovered per half: a risk-for-P&L trade, not an edge.
- The mirror ("stretched -> wait for break-even") is weakly positive and stable: pb15>=1 or pb60>=1 -> cap0, else current:
  10W +15k / +35k / 2026 +5k; 40W +237k / +246k / +43k, at +80..+570 uncovered.
- The only all-parts, all-widths improvement on BOTH $ and uncovered is about PRICE, not regime: "overBE < 0.12 -> pay
  the mark now, else rest at the current cap" (take a give-up immediately when it costs <= 12% of W past break-even):
  10W +9.6k / +3.2k / +4.9k, uncovered -33 / -38 / -23; 20W +15.9k / +55.1k / +16.2k; 40W +24.6k / +40.2k / +7.1k;
  day-level worst ~unchanged. Small; would need a full-engine sweep (governor, cap room) before any change.
- Caveat: 'actual' beats every static arm by a lot (v7-10 +$100k vs capCur) — the engine's give-up lapses when price
  recovers and its raise fills against the trigger bar's own extreme. Arm-vs-arm comparisons share one rule set.
Verdict: no momentum/band regime signal for "give up now"; do not build one. Candidate (not built): allowance-on-fill
(pay up to ~12% W only when it fills immediately) — sweep through runDay5m before proposing.

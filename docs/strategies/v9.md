## Intent

Take the **v7 signal exactly as it is** and add one mutation: proactively cover any position that reaches
0.80 × width, deeper than v8's 0.70. `index.js:214-215` calls it "the high-ceiling variant. Still paper
pending go/no-go".

Since 2026-09-07 v9 is an **experiment slot**. User's ruling: *"we want to use those slots to see if we
can tweak v6 or v7 rules to beat them, which is likely why they're so closely correlated."* High
correlation with the parent is the point of a mutation slot — **do not propose retiring v9 for it**.

## Open signal

**Identical to [v7](v7.md#open-signal)** — `v7Signal` with `{ fiveMin: true, beWrong: true }` and
`bidirectional: true`, every 5m bar: per-side intra-5m cover/flip; at 15m closes per-side trend-flip →
**be-wrong** (open the opposite side without covering the underwater one) → overextension → grind →
active-cover → gated trend continuation. No open-side difference at all from v7.

## Cover signal

v7's triggers (per side), plus:

| Trigger | Condition | Placed |
|---|---|---|
| **proactive** | uncovered position marking ≥ **0.80 × W**, no cover working | break-even resting order (`trader.js:1628-1637`) |
| be-wrong | places **no cover** (by design) | — |
| shared layer | continuous cover (minLock by width) laddered to break-even, give-up, governor deferral, floor raise, wings | README |

As with v8, continuous covering normally claims a position long before it is 0.80×W deep. Measured
2026-09-30: 68 proactive triggers across 113 v9 run-days (~0.6 per run-day) — rare, not dead.

## Open questions / suspected drift

1. **The slot holds a mutation at the wrong end of its own sweep** (0.80 barely fires; 0.70 was the peak
   and v8 already uses it). Per the slot policy this is when to swap it; no replacement has been proposed.
2. **Is the near-1.00 correlation mechanical?** Continuous covering claims positions before they reach
   0.80×W, so v9's one distinguishing flag rarely acts. Not tested as an explanation.
3. **Intent not documented:** why v9 pairs proactive covering with *be-wrong* rather than v6. The label
   "be-wrong + caps" implies caps plural; only one cap-like flag is set. The "$20k backstop" in the
   `FAMILIES` comment (`index.js:214`) no longer exists.
4. **"Paper pending go/no-go"** (`index.js:215`) — no go/no-go decision is recorded.

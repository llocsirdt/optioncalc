# v3 — "classic tent, risk-armed"

`{ key: 'v3', label: 'classic tent, risk-armed', signalFn: at15(classicSignal), signalCfg: {}, coverSelector: 'fixed', coverFillModel: 'resting', ...RISK_ARMED, coverGeometry: 'tent' }`
— `server/src/candle-spread/index.js` `FAMILIES`, with
`RISK_ARMED = { continuousCoverArmFrac: 0.20, continuousCoverOppRatio: 1.0 }` just above it.

Shared machinery: [README.md](README.md#shared-machinery-read-this-before-any-family-file). Triggers and
mechanisms: [signals.md](signals.md).

## Intent

Measure the **covering-POLICY axis** with geometry held at `tent`, so v0-vs-v3 is a clean A/B: should a
cover be rested the instant a position opens (v0), or only once the book or the position has *earned*
one? The stated case for arming (the `RISK_ARMED` comment in `index.js`; the ARMING comment in `trader.js` `placeContinuousCovers`) is
the failure mode instant covering cannot see — a couple of deep winners sitting through a reversal while total
book risk stays low. v3 is the **only family where continuous covers do not go on at birth**.

## Open signal

Identical to v0-v2: `classicSignal` at 15m closes only (`signals/classic-signal.js:7-24`) — green + new
high → **bull**; red + new low → **bear**. Signal on /NQ, pricing on NDX, strikes by placement G.

## Cover signal

Same triggers as v0, but **continuous** is gated. Each pass, per filled uncovered position with no cover
working, a continuous cover is placed only if **either** arm holds (`trader.js`
`placeContinuousCovers`):

| Arm | Condition | Meaning |
|---|---|---|
| **(a) book risk** | `−bookFloorNow ≥ 0.20 × lossTarget` | the governor's own measure of how close the day is to its working target |
| **(b) opportunity** | `W − openCost − coverMark ≥ 1.0 × coverMark` | this cover locks at least what it costs, regardless of book risk |

If neither holds, no order is placed that pass. A placement via arm (b) logs `cover-arm-opportunity`. Once
placed, the order life is the shared one: lock target `W − openCost − minLock`, cover ladder toward
break-even, stall cover after 15 min, give-up at 20 points through the short strike (README). At 20/40W the
cover's strike comes from the cover range (v0 shared it until 2026-11-06; v0–v2 now skip it), and arm (b) is
tested on that range pick's mark.

**`lossTarget` per width** is 1,400 / 2,100 / 5,250 (cATM 2,450 / 5,250), so arm (a) trips far earlier on 10W/20W
than under the $5,000 target the arms were tuned on (2026-09-06). On `-unc` twins there is no `lossTarget`, so arm
(a) can never trip and covering is opportunity-only (the `buildVariants` comment in `index.js`; same note
in `buildUncapped`).

Because arming leaves positions without a cover working, the **reversal** trigger can actually place
orders on v3, unlike v0-v2.

## Trend / reversal recognition

Identical to v0 — single 15m candle direction plus the prior-extreme break.

## Distinguishing config

| Flag | v3 | v0 |
|---|---|---|
| `continuousCoverArmFrac` | **0.20** | unset (always armed) |
| `continuousCoverOppRatio` | **1.0** | unset |
| `coverGeometry` | `'tent'` (same) | `'tent'` |
| `coverRange*` / `giveUpGeometry` at 20/40W | 9 / 2 / 0.02 / `'inside'` | unset (since 2026-11-06) |
| `lossMax` / `lossTarget` | 2,000 / 1,400 · 3,000 / 2,100 (floored from tuned 2,500) · 7,500 / 5,250 (ceiling, from the generic width cap) | 2,000 / 1,400 · 4,500 / 3,150 · 6,000 / 4,200 |
| `-cATM` `lossMax` / `lossTarget` | 3,500 / 2,450 · 7,500 / 5,250 | 7,000 / 4,900 · 7,500 / 5,250 |
| `continuousCoverMinLockFrac` | 0.10 / 0.20 / 0.20 | same |

v3-10 is also named in `CAPPRES_LIVE` (`index.js`), but its 1×W preset is always overwritten by
`TUNED_CAPS` (`['v3-10', 2000]`, applied after the preset in `applyExperiments`).

**Why 0.20 / 1.0:** the 70-combination arming sweep (2026-09-06, the `RISK_ARMED` comment) found the opportunity arm
does nearly all the work and that a lower `oppRatio` is uniformly better ("the cheap covers are the ones that
pay"). That sweep ran under the old $5,000 `lossTarget`, the old minLock, and instant open fills.

## Lineage

- **Inherits from:** v0 exactly, including `coverGeometry: 'tent'`; since 2026-11-06 v3 also differs from v0 at
  20/40W by keeping the cover range, which v0–v2 no longer get.
- **Changed:** the covering *policy* only (`RISK_ARMED`).
- **Kept off the 10W plateau cover on purpose** (the plateau-cover comment above `applyPlateauCover`, `index.js`): "v3 stays tent so it differs from v0 by
  risk arming alone."
- **History:** the 2026-09-05 arrangement put all three geometries behind arming at 0.60 / 2.0, which the
  sweep then placed near the bottom of the grid; re-slotted 2026-09-06 so v3 alone carries arming at its
  best measured setting (the `FAMILIES` comment).

## Open questions / discrepancies

1. **The arming sweep is stale.** It was measured under a $5,000 `lossTarget`; today's v3 targets are
   1,400-5,250, so arm (a) trips several times earlier on 10W/20W. Whether 0.20 is still the right fraction —
   or the risk arm should key off `lossMax` — has not been re-swept.
2. **Opportunity-only arming loses on the uncapped twins** (baselines above). Whether the opportunity arm alone
   is a viable policy, or only works because the risk arm backs it, is not recorded.
3. **Cover-to-stack is a no-op in both engines; v3 is the one possible exception in the backtest.** Live, a
   governor-blocked open just logs `open-skip-governor` (`trader.js` `processCandleClose`); cover-to-stack
   (`coverToStackFreeBudget`) is wired only to the `capState` branch for `softCap`/`hardCap`/`riskCap`, all null on
   every variant since 2026-10-14. In the backtest, `lockDeepWinners` does run on governor blocks
   (`backtest-v6-5m.js` `runDay5m`; `opts-for.js` sets `coverToStack`/`coverToStackVsRisk`), but it skips any
   position with a resting cover, and a 250-day on/off A/B was byte-identical with zero locks (journal
   2026-11-06). v3's unarmed positions have no resting cover, so the backtest could in principle lock them where
   live would not; whether the A/B covered v3 is not recorded, so this is code-read, not measured.
4. **Stale comments:** the `FAMILIES` comment says "v1-v3 arm only on risk … 60% of lossTarget or … 2x its own cost" —
   only v3 arms, at 0.20 / 1.0. It also says "v0-vs-v1 is a clean A/B of the POLICY" — it is v0-vs-v3
   (v0-vs-v1 is geometry).
5. **Intent not documented:** why the two arms are OR'd rather than staged (e.g. opportunity-only early,
   risk-armed late).

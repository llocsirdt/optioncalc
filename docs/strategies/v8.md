## Intent

**v8 = v6 signal + proactive deep-ITM covering (0.80×W)**, on the shared governor. Since 2026-10-14 it is the v6
counterpart of v9 (v7 + the same): the 2026-10-14 comment read "so v8 = v6 + proactive cover + reopen and v9 = v7 +
the same: a readable comparison." Since 2026-11-06 reopen after a quick cover is on every v0–v9 variant, v6 and v7
included, so proactive cover is the one feature v8 adds to v6.

What changed on 2026-10-14 (user; the comment above the v8 entry in `index.js` `FAMILIES`):
- The soft **"churn" cap** (`softCap: 3000` + `exemptTrendStack`) is **OFF**. It capped the debit on uncovered,
  not-deep-ITM positions at a flat $3,000 — the pre-governor risk layer — and, flat across widths, allowed about
  one uncovered 40W position at a time. The feature stays in `capState` (`trader.js`), backlogged.
- `proactiveCoverFrac` **0.70 → 0.80**, the same as v9.
- `reopenOnCover` turned on for every v8 variant (fleet-wide v0–v9 since 2026-11-06).

Since 2026-09-07 v8 is an **experiment slot**, not a trading candidate. User's ruling: *"we want to use
those slots to see if we can tweak v6 or v7 rules to beat them."* Do not propose retiring it.

## Open signal

Identical to [v6](v6.md#open-signal) — `v6Signal` with `fiveMin: true`, every 5m bar, including
**cover-to-open-wait** (`coverToOpenWait: true` on every v8 variant).

Including **reopen after a quick cover** (`reopenOnCover`, every v8 variant including `-unc`/`-cATM`, as on v6):
after a cover fills, re-open the same side at the same strikes (or deeper ITM at no more than the price paid)
while NDX is still inside them and the 15m signal that opened it stands — full rule in [v7.md](v7.md#open-signal). Modelled in the
backtest since 2026-11-06.

No variant carries `softCap`, `hardCap` or `riskCap`, so `capState` never blocks an open.

## Cover signal

v6's signal covers (both sides; break-even resting tents on positions without a cover working), plus:

| Trigger | Condition | Placed |
|---|---|---|
| **proactive** | uncovered position, no cover working, spread marking ≥ **0.80 × W** | break-even resting **tent** (`selectCoverFixedMark`), note `proactive-deep-itm` (`trader.js` `processCandleClose` step (3b)) |
| shared layer | continuous cover (10W plateau `offset1` / minLock 0.05×W; 20/40W cover range / minLock 0.20×W), ladder, stall 15 min, give-up 20 pts, governor deferral, floor raise, wings, floor offsets | README |
| **cover-to-stack** | **never fires in either engine**. Live it runs only when `softCap`/`hardCap`/`riskCap` block an open (`capState` → `coverToStackFreeBudget`, `trader.js`), and all three are null since the churn cap went off. The backtest calls `lockDeepWinners` when the governor would block an open (`backtest-v6-5m.js` `runDay5m`; `coverToStackVsRisk` from `opts-for.js:78`), but it skips any position with a resting cover, and continuous cover gives every position one: a 250-day on/off A/B was byte-identical with zero locks (journal 2026-11-06) | — |

Engine order differs: the backtest runs proactive **before** continuous (`backtest-v6-5m.js` `runDay5m`, step (a0)
then (a0b)); live runs it **after** continuous and the reversal step. Under unarmed continuous covering a position normally
already has a cover working by the time it marks 0.80×W in both engines, so proactive rarely places an order.

## Trend / reversal recognition

Identical to v6. `proactiveCoverFrac` is a book-state threshold on how deep in the money a position has run,
not a market read.

## Lineage

- **Inherits from:** v6 exactly (signal, cadence, cover machinery, cover-to-open-wait).
- **Changed (2026-10-14):** churn cap off, `proactiveCoverFrac` 0.70 → 0.80, `reopenOnCover` on; 2026-10-16
  `coverToOpenWait` on. The label is now `'proactive'` (these docs had it as `'risk-capped'` on 2026-10-07).
- **Earlier history:** built against v7's *old* single risk cap ("blindly stops ALL opens once uncovered debit ≥
  cap"), retired for the day-loss governor on 2026-09-04. The v8 ablation (`scripts/candle-spread/ablate-v8.js`,
  2026-09-05) found `softCap` alone was the damage and the proactive cover was not the culprit. The user's
  2026-09-05 agreed direction for the slot — the cover-GEOMETRY axis (partial/fractional covers, near-the-money
  covers on deep-ITM) — was never built as a v8 feature.

## Open questions / discrepancies

1. **In the backtest the proactive cover only costs.** Every v8 row is below the matching v6 row on total, with no
   change in worst day and maxDD30 unchanged except 40W-cATM (worse). Whether it earns its place live is open (live, reopen also differed
   from v6 until 2026-11-06).
2. **Cover-to-stack does nothing in either engine.** `coverToStack: true` sits on every v0–v9 variant (and v9sg,
   v9ob, v12, v13), but live it can fire only behind a legacy cap that no variant has; the backtest calls
   `lockDeepWinners` on governor blocks but it skips every position with a resting cover, so it never locks
   (250-day on/off A/B byte-identical, zero locks, v9-20 with 804 governor blocks; journal 2026-11-06). The user has
   decided to fix it; nothing is built yet.
3. **Stale comments:** `capState`'s header comment (`trader.js`) still calls the caps "v8 risk caps", and the cap-blocked call site
   in `processCandleClose` says "else skip (existing v8 behavior)".
4. **The churn cap's future is backlogged** (the v8 comment in `index.js` `FAMILIES`): the machinery stays, no variant uses it.

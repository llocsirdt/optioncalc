## Intent

Two ideas layered on the **v6 signal, unchanged**:

1. A **"churn" cap** limiting at-risk debit in chop but not in a trend. Built because v7's *original*
   single risk cap "blindly stops ALL opens once uncovered debit ≥ cap — no trend-vs-chop distinction"
   (experiments log). `exemptTrendStack` is the direct implementation of *don't cap trend-stacking, do cap
   chop*.
2. **Proactive deep-ITM covering** — lock a leader once its spread marks ≥ 0.70 × width, which also
   stops it counting toward the at-risk cap.

Since 2026-09-07 v8 is an **experiment slot**, not a trading candidate. User's ruling: *"we want to use
those slots to see if we can tweak v6 or v7 rules to beat them."* Do not propose retiring it.

## Open signal

Identical to [v6](v6.md#open-signal) — `v6Signal` with `fiveMin: true`, every 5m bar.

**What changes is which opens are ALLOWED** (live `capState`, `trader.js:355-366`, evaluated after the
governor gate at `:1729`; backtest `backtest-v6-5m.js:1320-1323`):

| Gate | Rule |
|---|---|
| day-loss governor | inherited (README) — projected book floor must stay inside `lossMax` |
| `softCap 3000` | sum of **at-risk** debit (uncovered **and** not marking ≥ 0.70×W) plus this open ≤ **$3,000** — absolute dollars, not width-scaled |
| `exemptTrendStack` | skip the soft cap entirely if every uncovered position is the same side as this open |
| cover-to-stack | if the soft cap blocks, lock uncovered winners marking ≥ 0.65×W (break-even resting covers) and retry (`trader.js:1729-1755`). v8 is the only family where the live cover-to-stack path can run |

## Cover signal

v6's signal covers (both sides; break-even resting orders on positions without a cover working), plus:

| Trigger | Condition | Placed |
|---|---|---|
| **proactive** | uncovered position marking ≥ **0.70 × W** with no cover working | break-even resting order (`trader.js:1628-1637`) |
| shared layer | continuous cover (minLock by width) laddered to break-even, give-up, governor deferral, floor raise, wings, **flies** | README |

Engine order differs: the backtest runs proactive **before** continuous (`backtest-v6-5m.js` a0 then a0b);
live runs it **after** continuous and the reversal step. Under unarmed continuous covering a position
normally already has a cover by the time it is 0.70×W deep in both engines. Measured 2026-09-30: 27
proactive triggers across 111 v8 run-days (~0.25 per run-day) — "rare, not dead".

## Trend / reversal recognition

Identical to v6. v8 adds one *book-state* notion — `stacking` (every uncovered position is the same side
as this open) — which exists only to disarm the soft cap.

The v8 ablation (`scripts/candle-spread/ablate-v8.js`, 2026-09-05 — pre-G, instant fills, but the
mechanism is structural):
- **The governor is innocent**; lifting it does not recover v8.
- **`softCap` alone is the damage** — removing it: 3.3× at $20, 2× at $10, 5.9× at $40. Root cause: a
  fixed $3,000 cap while spread cost scales with width; at 40-wide it permits about one position.
- **Scaling the cap does not save it** — larger caps converge monotonically on *no cap*. "The best version
  of the churn cap is no churn cap."
- **`exemptTrendStack` is a mitigation, not a feature**; **`proactiveCoverFrac 0.70` is not the culprit**.
- "Drop softCap, keep proactive" is strictly dominated by plain v6.

Later:
- **minLock re-sweep (2026-10-04):** capped v8-10 ret/DD 300 at 0.10 vs 186 at 0.20.
- **Caps:** v8-20 and v8-40-cATM want rungs *below* the 1.5×W floor ($2,500, $5,500) and are held at the
  floor — "coherence beats a measured preference" (`index.js:724-726`).

**User's call (2026-09-05):** keep the slot, give it a genuinely different angle — not another cap on v6,
not mean-reversion, not proactive covering alone (v9 owns that). **Agreed direction = the cover-GEOMETRY
axis** (partial/fractional covers, near-the-money covers on deep-ITM). **Not built.**

## Open questions / suspected drift

1. **The slot still holds the measured-losing mutation**, and the agreed replacement (cover geometry) has
   not been built. Note that wings, flies and floor raise — shape tools close to that brief — are now
   fleet-wide, so they would no longer distinguish v8.
2. **Comment drift about cap scaling:** `index.js:163` says "Caps here are the $20 values; buildVariants
   scales them by width"; the code copies `softCap` unscaled (`index.js:1093`) and `index.js:1066-1067`
   says caps are ABSOLUTE. The code follows *absolute*.
3. **v8-20-cATM is the one governed variant never tuned** — generic $7,000 cap with the BASE_RUNS $5,000
   `lossTarget` (every other governed variant has target = 0.7 × cap). Whether deliberate is not recorded.
4. **Cover-to-stack** (live) runs here because of `softCap`; with continuous covering on everything it has
   few candidates (positions with no cover working).

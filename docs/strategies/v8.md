# v8 — "risk-capped"

`{ key: 'v8', label: 'risk-capped', signalFn: v6Signal, signalCfg: { fiveMin: true }, softCap: 3000, proactiveCoverFrac: 0.70, exemptTrendStack: true, ...PORTED_COVER }`
— `server/src/candle-spread/index.js:183`

## Intent

Two ideas layered on the **v6 signal, unchanged**:

1. A **"churn" cap** that limits at-risk debit in chop but *not* in a trend. v8 exists because v7's
   original single risk cap "blindly stops ALL opens once uncovered debit ≥ cap — no trend-vs-chop
   distinction. Measured: at a $3k cap it BLOCKED 1,064 opens (vs 1,022 allowed), 34% were
   same-direction trend-stacking … The user does this on purpose; the cap shouldn't stop it."
   (experiments log). `exemptTrendStack` is the direct implementation of *don't cap trend-stacking,
   do cap chop*.
2. **Proactive deep-ITM covering** — lock a leader once its spread marks ≥ 0.70 × width, which also
   stops it counting toward the at-risk cap.

Since 2026-09-07 v8's **role** is different from its content: it is an **experiment slot**, not a
trading candidate. User's ruling: *"we want to use those slots to see if we can tweak v6 or v7 rules
to beat them."* Do not propose retiring it.

## Open signal

Identical to [v6](v6.md#open-signal) — `v6Signal` with `fiveMin: true`, no `at15` wrapper, acting on
every 5m bar:
- intra-15m bars: cover (and flip if 15m agrees) on a 2-bar-confirmed 5m structural reversal;
- 15m closes: trend-flip → overextension reversal → grind → active-cover → gated trend continuation.

**What changes is which opens are ALLOWED**, not which are signalled
(`backtest-v6-5m.js:882-897`, `trader.js:182-…`):

| Gate | Rule |
|---|---|
| `softCap 3000` | the sum of **at-risk** debit (uncovered **and** not deep-ITM) plus this open must be ≤ $3,000 |
| `exemptTrendStack` | **skip the soft cap entirely** if every uncovered position is the same side as this open — i.e. we are stacking a trend, not churning chop (`backtest-v6-5m.js:889-891`) |
| day-loss governor | inherited from `BASE_RUNS` — the projected book floor must stay inside `lossMax` |

## Cover signal

v6's triggers, plus one:

| Trigger | Condition | Placed | Fills |
|---|---|---|---|
| **proactive** (new) | any uncovered position whose spread marks ≥ **0.70 × W** (deep ITM → the offsetting tent is cheap) | resting order at `W − openCost` on that bar | when the real mark reaches it |
| intra-5m early cover / trend-flip / overextension / grind / active-cover | as v6 | resting, `W − openCost` | same |
| `continuous` (shared) | every 5m bar, unarmed → at birth, target `W − openCost − 0.35×W` | | same |
| `lock` (shared) | governor cover-to-continue | `W − openCost` | same |

Order of evaluation in the backtest: proactive runs **before** continuous
(`backtest-v6-5m.js:525-531` then `:533-587`), so a deep-ITM position gets the proactive tag; in the
live trader proactive runs **after** the reversal step (`trader.js:746-757`), by which point
continuous has already claimed everything.

## Trend / reversal recognition

Identical to v6 — structural trend = 15m close + 15m 9EMA vs the 15m midline; intra-15m reversal =
the 5m structural pair against the held side for two consecutive 5m bars.

v8 adds one *non-signal* notion of trend: `stacking` — "every uncovered position is the SAME side as
this open" (`backtest-v6-5m.js:891`). This is a book-state test, not a market read, and it exists only
to disarm the soft cap.

| `exemptTrendStack` | **true** | absent |

## Lineage

- **Inherits from:** v6 exactly (signal, cadence, cover machinery).
- **Changed:** adds `softCap` + `exemptTrendStack` + `proactiveCoverFrac`.
- **Originally motivated by** v7's *old* meaning (the single "be patient" risk cap) blocking
  trend-stacking. That risk-cap regime was retired on 2026-09-04 and replaced by the day-loss
  governor — so **v8's premise no longer exists**, but the flags remain.

## Findings

Committed baseline (765 days):

| variant | total $ | worst day $ | win % | opens/day | maxDD30 $ | ret/maxDD30 | peak capital $ |
|---|---|---|---|---|---|---|---|
| v8-10 | 959,816 | −5,640 | 70% | 14.2 | −13,920 | 69.0 | 1,456 |
| v8-20 | 654,562 | −6,985 | 63% | **8.8** | −29,854 | 21.9 | 2,894 |
| v8-40 | 561,900 | −9,000 | 60% | **6.9** | −46,594 | 12.1 | 6,015 |

**v8 is the worst family in the roster at $20 and $40** — a quarter of v6's total on the same signal.

The v8 ablation (`scripts/candle-spread/ablate-v8.js`, 2026-09-05) is unusually conclusive:
- **The governor is innocent.** Keep% (governed ÷ ungoverned) = 100% / 119% / 50% at $10/$20/$40;
  lifting the governor does not recover v8, and at $20 v8 is *worse* ungoverned. Two caps fighting
  would show as recovery-when-lifted. There is none.
- **`softCap` alone is the damage.** Removing it: $396,760 → **$1,325,771** at $20 (3.3×); 2× at $10;
  **5.9× at $40**. Holds ungoverned too.
- **Root cause:** `softCap 3000` is a *fixed dollar* cap while spread cost scales with width. At the
  0.65 ceiling a $40 spread costs up to $2,600, so $3,000 permits **one position**. It strangles
  position count — visible directly in opens/day (6.9 at $40 vs v6's 28.4).
- **Scaling the cap does not save it.** 6× / 12× / 20× per-spread cost gives $836k / $1,273k /
  $1,326k — monotonic convergence on *no cap*, never beating it. "The best version of the churn cap
  is no churn cap — the CONCEPT is dead for v8, not just the calibration."
- **`exemptTrendStack` is a mitigation, not a feature** — removing it makes v8 *worse* ($260,455). It
  only exists because `softCap` exists.
- **`proactiveCoverFrac 0.70` is not the culprit** — removing it barely helps ($468,338).
- "Drop softCap, keep proactive" is **strictly dominated by plain v6** at every width on both total
  and ret/DD. "It is v6 with ~3.6% shaved off by proactive covering, not a strategy."
- v8-20 is the **only variant in the roster where wing conversion hurts on both metrics**.

**User's call (2026-09-05):** keep the v8 slot, but give it a genuinely different angle. Constraints
established by the ablation: v8 must **not** be (a) another cap on v6 — any constraint on v6 is
dominated by v6; (b) mean-reversion — explored and parked; (c) proactive covering alone — v9 owns
that axis. **Agreed direction = the unexplored cover-GEOMETRY axis** (partial/fractional covers,
peak→floor wing conversion, near-the-money covers on deep-ITM) — additive shape changes that retain
upside rather than capping it. **Not built.**

## Open questions / suspected drift

1. **🚨 CONFIRMED DRIFT — "continuous cover" is not what the user meant.** As in v6/v7: the code rests
   a cover on **every uncovered position on every bar** (`backtest-v6-5m.js:560-587`,
   `trader.js:669-698`), i.e. at birth. Intent was a **ladder** — a new open triggers covering a prior
   one. The ladder is implemented only as the unwired `opts.coverPriorOnOpen` backtest flag
   (`backtest-v6-5m.js:855-861`) with no live counterpart (`trader.js:838-840` is a placeholder).
   **This has a specific extra cost for v8:** continuous covering claims every position before
   `proactiveCoverFrac` can, so v8's second mechanism is largely inert in live — consistent with the
   ablation finding that removing proactive "barely helps".
2. **CONFIRMED — contradictory statements about cap scaling.** `index.js:133` says "Caps here are the
   $20 values; buildVariants scales them by width". `buildVariants` does **not** scale `softCap`
   (`index.js:316`), and `index.js:289-291` says the opposite ("Dollar risk caps are ABSOLUTE"). The
   code follows *absolute*, and the ablation identifies exactly that as the cause of v8-40's
   collapse. One of the two comments is wrong and neither is dated.
3. **v8's premise has expired.** It was built against v7's old single risk cap, which no longer
   exists. Nothing in the code records that the motivation is gone.
4. **The slot is knowingly holding a losing mutation.** That is the stated policy ("both slots are
   currently holding a mutation that LOSES, which is exactly when to try a different one"), not a
   defect — but the agreed replacement direction (cover geometry) has not been built, so v8 is
   currently spending three variants' worth of compute on a measured dead end.
5. **`minLock 0.35` for v8 is inferred**, not swept (`index.js:278`).
